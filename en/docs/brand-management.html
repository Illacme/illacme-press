🏷️ Brand Management & Multi-Site (Imprint)

Within Illacme Plenipes, every publishing project functions as an independent "Publishing Brand (Imprit)". This guide will walk you through leveraging a multi-brand architecture to achieve absolute physical isolation management across multiple sites, libraries, and channels.

🏛️ 1. What is a "Publishing Brand (Imprint)"?

When a creator manages content across multiple domains (e.g., personal tech blogs, academic research columns, corporate product documentation, and lifestyle travel essays), traditional publishing tools often require deploying multiple independent programs or mixing content chaotically within the same database.

Illacme Plenipes Multi-Brand Architecture:
- Physically Isolated Storage: Each brand possesses its own directory imprints/{brand}/, storing configuration independently (config.imprint.yaml), historical ledgers (usage_ledger.json), and synchronization status.
- Independent Manuscript Library: Brand A can bind to /Vaults/TechDocs, while Brand B binds to /Vaults/DailyLife.
- Independent Thematic Design: Technical sites may adopt Docusaurus or Starlight, whereas personal blogs utilize the Sovereign cyberpunk style.
- Independent Distribution Matrix: Technical articles sync to GitHub Pages and Dev.to, while essays sync to WeChat Official Accounts and Substack.

🚀 2. How to Create and Switch Brands

Method One: Visual Operations in the Governance Center

  1. Open your browser and navigate to the Governance Center: http://127.0.0.1:43212/dashboard/
  2. Navigate to [Brand Imprinting & Modes] → [Brand Management (Imprints)]
  3. Click the "➕ Create New Brand" button, enter the brand alias (e.g., tech_weekly) and display name
  4. Configure the library path, theme style, and distribution credentials for this brand
  5. Click "Activate & Switch"; the system will hot-switch the current workspace in milliseconds!

Method Two: Command-Line Rapid Operations

# 1. 唤醒出版引擎
python3 plenipes.py

# 2. 在交互菜单中选择 [1] 切换出版品牌，或使用参数指定启动：
python3 plenipes.py --imprint tech_weekly --sync

🛡️ 3. Special Positioning of the Default Brand (Default Imprint)

  • Ready-to-Use Showcase: The system's built-in imprints/default is an official standard template.
  • Full-Feature Experience Privilege: When in the default brand with the Sovereign theme activated, the system defaults to unlocking all advanced professional edition features.
  • Recommended Practice: We recommend keeping default as a system function testbed and using newly created exclusive brands to host your production-level actual libraries.
