🏛️ Physical Isolation Architecture & Technical Principles

Illacme Plenipes adheres to the philosophy of "Sovereign Absolute Isolation." This chapter will detail the system's core architecture, physical data flow, and security design.

🔒 Four Major Physical Isolation Red Lines

1. Original Manuscript Repository Read-Only Red Line (Vault Read-Only Sentry)

The system employs read-only scanning and hash indexing for the creator's original manuscript directory (vault/), never writing any temporary build files or cache databases into the original manuscript directory.

2. Imprint Physical Isolation (Imprint Sovereignty)

Each brand possesses an independent file tree (imprints/{brand}/), with its configuration files, metadata ledger (ledger.db), binding artifacts, and logs all independently isolated to prevent interference.

3. Mother Theme Read-Only Isolation (Mother Theme Isolation)

The official theme templates provided by the system (themes/) serve as clean, read-only Mother Themes. All build artifacts and user static outputs must be directed to their respective brand directories or the global dist/, strictly prohibiting any pollution of the mother theme directory.

4. Local Encryption Isolation for Compute Credentials (Credential Vault)

All API keys are encrypted with sovereign ciphertext (enc:...) upon disk write; plaintext keys are strictly prohibited in the main configuration file to prevent key leakage via code commits.
