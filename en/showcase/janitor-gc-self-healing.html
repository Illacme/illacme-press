🛠️ Core Mechanisms and Self-Healing Architecture

1. 📜 Bidirectional Physical Fingerprint Ledger

The system maintains a global fingerprint ledger for the authoring vault in a local SQLite database and cache directory:
* Records the SHA-256 hash and modification timestamp for each source document (Markdown, images, attachments);
* Records all derived artifacts generated from that file (multi-language HTML, OpenGraph social cards, image hosting reference URLs).

2. 🧹 Janitor Physical Scrubber (Ghost Asset Scrubber)

Janitor automatically intervenes on every incremental compilation or sync trigger:
1. Reverse Comparison: Iterates through all HTML and resource files in the artifact output directory to identify isolated files with no corresponding source document;
2. Safe Reclamation: Automatically physically deletes these ghost files and outdated route mappings within milliseconds, preventing 404 broken links on the website;
3. Sitemap and Index Synchronization Correction: Automatically removes deleted nodes from the sitemap.xml and graph.json universe topology.

3. ♻️ LRU Cache Governance and Automatic Degradation Strategy

  • In the "Storage Adaptation" panel of the Governance Center, creators can flexibly set limits for compute cache (Janitor GC), such as retaining the most recent 30 days or 500MB;
  • When local AI translation paragraph caches or generative image assets exceed thresholds, the engine prioritizes evicting the oldest and unlocked low-frequency paragraphs, ensuring the system remains lightweight even after years of operation.
