🚀 核心動作原理：段落レベルのシャドウキャッシュ (BlockShadowCache)

従来の全文翻訳では、微細な修正でも LLM を全量再呼び出しするため、膨大なトークンが浪費されます。Illacme Plenipes は意味論的段落分片を採用しています：

  1. 精密なスライシング：Markdown パーサーが文書を読み込み、見出し、段落、コードブロック、引用、表など独立した意味論的ブロックに分解します。
  2. フィンガープリント検証：各ブロックについて SHA-256 構造フィンガープリントを計算します。
  3. シャドウキャッシュの再利用：翻訳済みの段落は SQLite シャドウデータベースから秒単位で読み取り、変更があった単一の段落のみに対して AI 呼び出しを行います。
  4. 90% 以上の計算資源削減：API 請求額を大幅に削減し、インクリメンタル同期の待機時間を著しく短縮します。

🛠️ ローカルおよびクラウドノードの構成例

ガバナンスセンターまたは config.yaml / config.imprint.yaml で主要ノードと予備ノードを構成します：

translation:
  enable_ai: true
  primary_node: lmstudio_local    # 主用算力节点
  primary_model: qwen/qwen3.5-9b  # 主用模型名称
  fallback_node: ollama_local     # 备用容灾节点
  fallback_model: qwen/qwen3.5-9b # 备用模型名称
  temperature: 0.2                # 翻译温度（推荐 0.1 ~ 0.3）
  max_tokens: 4096                # 最大输出 Token

🛡️ 産業用フォールトトレラントおよび自己修復メカニズム

  • 指数関数的バックオフ再試行 (Exponential Backoff)：429 リクエスト制限やネットワークの瞬間的断線が発生した際、自動的に段階的な再試行を行います。
  • 自動障害切り替え (Failover)：主要ノードが連続して失敗すると、自動的に予備の災害復旧ノードに切り替えます。
  • 純粋なプレースホルダーバイパス (Mask Bypass)：コード、数式、タグブロックはモデル推論を自動的に識別してスキップし、ハルシネーションを 100% 防止します。
