🏛️ 物理隔離アーキテクチャと技術原理

Illacme Plenipes は「主権絶対分離（Sovereign Isolation Architecture）」の哲学に従います。本章では、システムの核心となるアーキテクチャ、物理的なデータフロー、およびセキュリティ設計を詳細に解説します。

🔒 四大物理隔離の鉄則

1. 原稿文庫只読鉄則 (Vault Read-Only Sentry)

システムはクリエイターが所有する原稿ディレクトリ（vault/）に対して、只読スキャンとハッシュインデックスのみを実行し、原稿ディレクトリ内にいかなる一時的なビルドファイルやキャッシュデータベースも書き込まない。

2. 出版ブランドの物理的隔離（インプリント主権）

各ブランドは独立したファイルツリー（imprints/{brand}/）を有し、その構成ファイル、メタデータ帳簿（ledger.db）、装幀生成物およびログはすべて個別に隔離され、相互干渉しない。

3. テーマ母本只読隔離 (Mother Theme Isolation)

システム標準の公式テーマテンプレート（themes/）は、クリーンな読み取り専用マザーテーマとして機能します。すべてのビルド产物とユーザー静的出力は、対応するブランドディレクトリまたはグローバル dist/ に書き込まれ、マザーテーマディレクトリの汚染は厳禁です。

4. 計算力キーのローカル暗号化隔離 (Credential Vault)

すべての API キーはディスクに保存される際、主権暗号文で暗号化されます（enc:...）。主設定ファイルには平文キーの保存を厳禁し、コードコミットによるキー漏洩を防ぎます。
